# 00. 처음 보는 사람·AI에게 넘겨 바로 끝내는 Datest 셋업 가이드

이 문서 한 장이면 **백지 상태의 새 환경에서 AI가 100% 재현**할 수 있도록 구성했습니다.

> **보안 규칙:** 실제 토큰/사용자ID/채널ID는 문서에 적지 말고, 실행 직전에 환경변수로만 주입하세요.

---

## 0) 목표 한 줄 정의

- Windows(또는 Linux)에서 GPT만으로도, 네이버클라우드 VM 하나와 이 Git 저장소만 기준으로 `datest` 자동 구축을 완료한다.
- 사람이 직접 입력해야 하는 값은 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USERS`, `TELEGRAM_HOME_CHANNEL` 3개뿐이다.
- `default` 프로필을 유지하고 `datest` 프로필만 별도 운영한다.

---

## 1) 서버 측 준비 (UI는 수동 1회만)

1. 네이버클라우드에서 Ubuntu 22.04/24.04 VM 생성
2. SSH 키 등록 + 퍼블릭 IP 확보
3. 보안그룹: SSH(22) 허용

> VM 생성/SSH 승인까지는 수동 단계이지만, 그 이후는 스크립트가 자동 진행한다.

---

## 2) Windows에서 바로 실행할 원클릭 블록 (GPT가 실행)

윈도우에서 Git Bash, WSL, 또는 원격 SSH 세션 중 아무 쪽에서나 실행 가능.

```bash
ssh -i ~/.ssh/<YOUR_KEY>.pem ubuntu@<SERVER_PUBLIC_IP>

sudo apt update && sudo apt upgrade -y

# 저장소 클론
mkdir -p /tmp
cd /tmp
git clone https://github.com/sodam3156/Simple-hermes-setting-with-Naver-cloud-Server.git
cd /tmp/Simple-hermes-setting-with-Naver-cloud-Server

# 실행값 주입
export TELEGRAM_BOT_TOKEN=<TELEGRAM_BOT_TOKEN>
export TELEGRAM_ALLOWED_USERS=<USER_ID_OR_IDS_COMMA_SEPARATED>
export TELEGRAM_HOME_CHANNEL=<CHAT_OR_CHANNEL_ID>

# 실무기본값
export CREATE_PROFILE=1
export CREATE_CRON=1
export START_GATEWAY=0      # 첫 실행은 0 권장, 검증 후 1로 변경
export AUTO_VERIFY=1
export AUTO_INSTALL_DEPS=1  # 누락 패키지 자동 설치
export DRY_RUN=0

# datest 경로 보정은 필수
export PATH="$HOME/.local/bin:$PATH"

chmod +x scripts/bootstrap-datest.sh
bash scripts/bootstrap-datest.sh
```

### 스크립트가 자동 처리
- Hermes 미설치 시 자동 설치
- `datest` profile(datest) 생성/유지
- `~/.hermes/profiles/datest/.env` 생성(실 값 저장, 민감값은 해당 파일 외 유출 없음)
- `SOUL.md`, reminder 스크립트, 일정 JSON 배치
- cron 4개 등록(동명 기존 삭제 후 재등록)
- `AUTO_VERIFY` 기준으로 핵심 동작 검증

## 3) 완료 검증(필수 4개)

아래 명령이 통과해야 완전 완료입니다.

```bash
export PATH="$HOME/.local/bin:$PATH"

hermes profile show datest
hermes profile list
datest send --list telegram

datest cron list

datest cron run datest-daily-goal
datest cron run datest-weekly-goal
datest cron run datest-monthly-goal
datest cron run datest-2h-schedule

datest cron runs datest-2h-schedule --limit 3
```

> 위 중간에 하나라도 실패하면 블록 아래의 복구 블록을 그대로 진행하세요.

## 4) 실패 복구 블록 (AI가 그대로 재사용)

### A) `datest: command not found`

```bash
export PATH="$HOME/.local/bin:$PATH"
which datest || true
hermes --version
bash scripts/bootstrap-datest.sh
```

### B) cron는 보이는데 알림이 오지 않음

```bash
export PATH="$HOME/.local/bin:$PATH"
datest send --list telegram
datest cron list
datest cron runs datest-2h-schedule --limit 5
datest gateway status
```

### C) gateway 시작 실패

```bash
datest gateway stop || true
datest gateway start
ps -ef | grep -i hermes | grep datest || true
```

### D) 실행 후 값 반영 확인(채팅 공유 금지)

```bash
cat "$HOME/.hermes/profiles/datest/.env"
```

---

## 5) 운영 모드 전환(완료 후)

1. 최초 실행에서 `START_GATEWAY=0`
2. 알림/cron 검증이 정상인 것을 확인
3. 아래 한 줄만 실행해 수신 데몬 시작

```bash
export START_GATEWAY=1
bash scripts/bootstrap-datest.sh
```

## 6) Windows + GPT만 있는 환경을 염두에 둔 운영 원칙

- 가능한 **답변이 아닌 실행 블록**만 던져서 처리
- 토큰/ID는 placeholder 값이 아니라, 반드시 실행 직전 주입값만 사용
- 실패하면 같은 블록을 그대로 재실행, `DRY_RUN=1`로 먼저 점검 후 본 실행

### 자동 완결형 운영값(예시)

```bash
export CREATE_PROFILE=1
export CREATE_CRON=1
export START_GATEWAY=0
export AUTO_VERIFY=1
export AUTO_INSTALL_DEPS=1
export DRY_RUN=0
```

## 7) 원격 동기화(매번 붙여넣기 최소화)

`push`는 매번 GitHub ID/PAT를 묻는 게 제일 큰 병목이야. 이 저장소는 아래 스크립트로 1회만 토큰을 등록하면 반복 입력 없이 동기화된다.

```bash
chmod +x scripts/git-sync-simple.sh
```

### 7-1) 가장 실용적인 1회 설정(토큰)

```bash
# 1회만 실행
mkdir -p "$HOME/.config/simple-hermes"
printf '%s\n' "ghp_xxx_YOUR_TOKEN" > "$HOME/.config/simple-hermes/github-token"
chmod 600 "$HOME/.config/simple-hermes/github-token"

# 매일 동기화는 한 줄
bash scripts/git-sync-simple.sh
```

### 7-2) 즉시 푸시(토큰 임시 주입)

```bash
export GIT_PUSH_TOKEN=ghp_xxx_YOUR_TOKEN
bash scripts/git-sync-simple.sh
```

### 7-3) SSH deploy key만 쓰는 경우 조심

현재 SSH 별칭이 쓰기 권한이 없는 `deploy key`면 `Permission denied`가 납니다. 이때는 **HTTPS+토큰 경로**로만 푸시하세요.

### 7-4) 스크립트 동작 요약
- 토큰(env) 우선
- 없으면 `gh auth` 사용
- 둘 다 없으면 저장된 HTTPS 자격증명 시도
- 모두 실패하면 1회 설정 절차를 안내

## 8) FAQ
- **왜 한 문서로 되는가?**
  - UI 수동 1단계 후, 설치/복구/운영 모두 이 문서 내부에서 끝나기 때문입니다.
- **기존 `default`는 건드리지 않나?**
  - 네, `datest`만 별도 운영됩니다.
- **기존 `.env` 보존은?**
  - 현재 자동화는 새 값으로 갱신합니다. 기존 보관이 필요하면 백업 후 실행하세요.
