# 05. Cron 등록 및 검증

`datest`는 리마인더 스크립트를 **no-agent(스크립트 stdout 그대로 전달)** 모드로 운영하면 안정적입니다.

## 1) 기존 datest cron 정리(옵션)

이미 실행 중인 기존 job이 있다면 이름으로 삭제 가능:

```bash
PATH=$HOME/.local/bin:$PATH datest cron list
PATH=$HOME/.local/bin:$PATH datest cron remove datest-daily-goal
PATH=$HOME/.local/bin:$PATH datest cron remove datest-weekly-goal
PATH=$HOME/.local/bin:$PATH datest cron remove datest-monthly-goal
PATH=$HOME/.local/bin:$PATH datest cron remove datest-2h-schedule
```

## 2) 새로 등록 (권장 값)

```bash
# 일간 목표
PATH=$HOME/.local/bin:$PATH datest cron create "0 9 * * *" "" \
  --name datest-daily-goal \
  --deliver telegram:<TELEGRAM_CHAT_ID> \
  --script datest_goal_daily.py --no-agent

# 주간 목표
PATH=$HOME/.local/bin:$PATH datest cron create "0 9 * * 0" "" \
  --name datest-weekly-goal \
  --deliver telegram:<TELEGRAM_CHAT_ID> \
  --script datest_goal_weekly.py --no-agent

# 월간 목표
PATH=$HOME/.local/bin:$PATH datest cron create "0 9 1 * *" "" \
  --name datest-monthly-goal \
  --deliver telegram:<TELEGRAM_CHAT_ID> \
  --script datest_goal_monthly.py --no-agent

# 2시간 주기 일정
PATH=$HOME/.local/bin:$PATH datest cron create "every 120m" "" \
  --name datest-2h-schedule \
  --deliver telegram:<TELEGRAM_CHAT_ID> \
  --script datest_goal_2h.py --no-agent
```

`--script`는 `~/.hermes/scripts/` 또는 `~/.hermes/profiles/datest/scripts/`에 있는 파일명을 받습니다.

## 3) 동작 확인

```bash
PATH=$HOME/.local/bin:$PATH datest cron list
```

예상 항목:
- `datest-daily-goal`  / `0 9 * * *`
- `datest-weekly-goal` / `0 9 * * 0`
- `datest-monthly-goal` / `0 9 1 * *`
- `datest-2h-schedule` / `every 120m`

## 4) 수동 트리거로 테스트

```bash
PATH=$HOME/.local/bin:$PATH datest cron run datest-daily-goal
PATH=$HOME/.local/bin:$PATH datest cron run datest-weekly-goal
PATH=$HOME/.local/bin:$PATH datest cron run datest-monthly-goal
PATH=$HOME/.local/bin:$PATH datest cron run datest-2h-schedule
```

출력/실행 로그:

```text
Ran now: succeeded.
```

또는

```text
done: completed <job_id>
```

## 5) 크론 실행 이력

```bash
PATH=$HOME/.local/bin:$PATH datest cron runs datest-2h-schedule --limit 3
```

## 6) 2시간 job의 “무음(no-op)” 체크

현재 일정이 하나도 없으면 빈 문자열을 반환하도록 설정되어 있으므로 cron이 성공했더라도 메시지가 비어 있을 수 있습니다.
이는 스팸을 줄이기 위한 정상 동작입니다.
